# Newsletter Setup

## Architecture

Astro renders the public forms and exposes Vercel functions at `/api/newsletter/subscribe` and `/api/newsletter/unsubscribe`. These endpoints validate requests, apply same-origin and rate-limit checks, and call a private Google Apps Script web app with a shared secret. Apps Script owns Google Sheets access and sends individual Gmail messages. The browser never receives the Sheet ID, webhook secret, Gmail credentials, or AI key.

## 1. Create and secure the Sheet

Create a private Google Sheet owned by the ministry Google Workspace account. Share it only with authorised newsletter administrators; never enable public editing. Copy its ID from the URL. Create a bound or standalone Apps Script project, add `integrations/google-apps-script/newsletter.gs`, and apply `appsscript.json` if using `clasp`.

In Apps Script **Project Settings → Script properties**, add:

```text
NEWSLETTER_SPREADSHEET_ID=<private sheet id>
NEWSLETTER_WEBHOOK_SECRET=<long random secret>
PUBLIC_SITE_URL=https://ometomeni.org
NEWSLETTER_FROM_NAME=Omet Omeni Ministries
NEWSLETTER_REPLY_TO=hello@ometomeni.org
NEWSLETTER_BATCH_SIZE=40
NEWSLETTER_SENDING_DISABLED=false
```

Run `setupNewsletterSheets` once and authorise it. It creates `Subscribers`, `Campaigns`, and `Email Log` with the required columns. IDs, timestamps, consent records, and unsubscribe tokens are generated by Apps Script. Do not reorder or rename columns without updating the script.

## 2. Deploy the web app

Choose **Deploy → New deployment → Web app**. Execute as the ministry account that owns the Sheet and Gmail sender. Select the access setting that permits the Vercel server to call the deployment, then copy the `/exec` URL. The shared secret still authenticates every operation. Google documents the current deployment process in its [Apps Script web-app guide](https://developers.google.com/apps-script/guides/web).

In Vercel, set these for Preview and Production:

```text
GOOGLE_APPS_SCRIPT_NEWSLETTER_URL=<the /exec deployment URL>
NEWSLETTER_WEBHOOK_SECRET=<the identical long random secret>
NEWSLETTER_FROM_NAME=Omet Omeni Ministries
NEWSLETTER_REPLY_TO=hello@ometomeni.org
```

Redeploy after changing environment variables. Rotate a secret by updating Apps Script first, updating Vercel immediately, deploying, and testing. Never put either value in Git or a `PUBLIC_` variable.

## 3. Test subscriptions and unsubscribe

Use a Vercel Preview deployment. Submit a new address and verify one `ACTIVE` row, ISO timestamps, consent, source, a random token, one welcome email, and a safe `WELCOME` log entry. Submit it again and verify `DUPLICATE` without another welcome email. Open the email unsubscribe link, confirm, and verify `UNSUBSCRIBED` plus `Unsubscribed At`. Resubscription must come through the form with fresh consent and produces `REACTIVATED`.

There is no privacy page yet. Add and legally review one before launch; do not invent a privacy policy in UI copy.

## 4. Create, approve, and schedule a campaign

Add a Campaigns row with a unique Campaign ID, name, subject, preview text, email-safe HTML body, plain-text body, and an optional JSON audience filter such as `{"location":"ACCRA"}` or `{"interest":"EVENTS"}`. Begin with `Status=DRAFT` and `Approved Status=NOT_APPROVED`.

An authorised reviewer must verify Scripture, dates, links, factual claims, the audience, plain-text fallback, and unsubscribe output. Only then set `Status=APPROVED`, `Approved Status=APPROVED`, `Approved By`, and an ISO-compatible Scheduled Date. Run `installNewsletterTrigger` once. Google notes that installable triggers run as their creator, so the ministry automation account should create it; see [installable triggers](https://developers.google.com/apps-script/guides/triggers/installable).

The sender locks campaign processing, sends one recipient per message, filters only `ACTIVE` subscribers, avoids already-attempted recipients, records counts, and checks remaining Gmail quota. To retry a reviewed failure, change its Email Log status from `FAILED` to `RETRY`, then use **Newsletter → Retry eligible failures**. Retries stop after two attempts.

## 5. Optional AI drafts

Set `AI_DRAFT_ENDPOINT` and `AI_API_KEY` only in Apps Script properties. The endpoint must return JSON containing `subject`, `previewText`, `htmlBody`, and `textBody`. Call `createAiCampaignDraft(input)` from the editor. It always creates `DRAFT / NOT_APPROVED`; it cannot schedule or send. A human must verify all Scripture, dates, links, summaries, and claims before approval.

## 6. Operations, quotas, and incidents

Review Apps Script **Executions**, Gmail delivery, Campaign counts, and Email Log error categories. Logs intentionally omit message bodies and secrets. Google currently documents Apps Script email-recipient quotas separately for consumer and Workspace accounts and warns that quotas can change; check the [current quotas](https://developers.google.com/apps-script/guides/services/quotas) before every large send. This system is for a small list. Move to Brevo, MailerLite, Kit, or another compliant provider when volume, deliverability, analytics, suppression management, or governance requirements grow.

To stop sending during an incident, set `NEWSLETTER_SENDING_DISABLED=true` and delete or disable the campaign trigger. To stop new subscriptions too, remove `GOOGLE_APPS_SCRIPT_NEWSLETTER_URL` from Vercel and redeploy. Preserve unsubscribed records until an approved retention/deletion policy is adopted. Handle future access or deletion requests through an authorised administrator and documented identity verification.
